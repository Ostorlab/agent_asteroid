# CVE-2021-43798: Grafana plugin static-file path traversal

**[CVE-2021-43798](https://www.cve.org/CVERecord?id=CVE-2021-43798) is an
unauthenticated arbitrary file read** in Grafana (CWE-22, CVSS 3.1 7.5). Grafana
serves plugin assets from `/public/plugins/<id>/` and joins the remaining
request path to the plugin directory without confining it, so an anonymous GET
reads arbitrary files readable by the Grafana process.

**Affected:** Grafana 8.0.0-beta1 through 8.3.0
([GHSA-8pjx-jj86-j47p](https://github.com/grafana/grafana/security/advisories/GHSA-8pjx-jj86-j47p)).

**Fixed:** Grafana 8.0.7, 8.1.8, 8.2.7, 8.3.1 or later.

**Severity:** CVSS 3.1 7.5 (High) — `AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:N/A:N`.

## How does the detector verify the file read?

1. Grafana is attributed from its `/login` or `/` landing document.
2. For a short list of plugin ids bundled with every install (`alertlist`,
   `graph`, `table`, `text`, `prometheus`, `cloudwatch`, `mysql`,
   `elasticsearch`), `GET /public/plugins/<id>/../../../../etc/passwd` is sent
   with the literal `../` intact (the prepared URL is rebuilt from
   `urllib.parse.urlsplit` so requests does not collapse the dot segments).
3. A positive match requires HTTP 200, a `text/plain` content type and the host
   account listing (`root:...:0:N:`).
4. A random missing file under the same plugin must not return the marker, so a
   catch-all host is not reported.

Only the world-readable `/etc/passwd` is read. No credential or cookie is sent
and redirects are not followed.

## Remediation

Upgrade Grafana to 8.0.7, 8.1.8, 8.2.7, 8.3.1 or later. Restrict access to the
Grafana HTTP port and treat any file the Grafana process can read as
potentially disclosed.
