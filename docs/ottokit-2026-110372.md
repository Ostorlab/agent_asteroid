# CVE-2026-110372: OttoKit unauthenticated privilege escalation

**CVE-2026-110372 is an unauthenticated privilege escalation** in the OttoKit
(formerly SureTriggers) WordPress plugin (CWE-266, CVSS 3.1 9.8). When an admin
denies the SaaS connection, the plugin stores the fixed public string
`connection-denied` as the site API secret; the automation REST permission
callback compares the `st-authorization` bearer against it, so
`Bearer connection-denied` authenticates an attacker who can then create
administrator accounts.

**Affected:** OttoKit (SureTriggers) <= 1.1.40

**Fixed:** OttoKit (SureTriggers) 1.1.41

**Severity:** CVSS 3.1 9.8 (Critical) — `AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H`

## How does the detector verify it?

This is an **active, non-destructive** check that uses a token differential and
**creates no account**. It sends the same benign no-op action (an unknown
integration and event that the handler rejects *after* authentication) twice:

```
POST /wp-json/sure-triggers/v1/automation/action   Content-Type: application/json
  {"integration":"__ostorlab_probe__","type_event":"__noop__","selected_options":{}}

control  st-authorization: Bearer <random>            -> must be rejected (rest_forbidden)
inject   st-authorization: Bearer connection-denied   -> must pass the permission layer
```

A patched build rejects both tokens; a vulnerable build authenticates only the
magic token, which the handler then stops at the unknown integration without
creating anything. The check **creates no administrator, writes nothing and
changes no state** — it never sends the `create_user` event the real exploit
uses. Both requests are built in isolation so no scanner credential or cookie
reaches the wire; redirects are not followed.

**Limitation:** the check confirms the authentication bypass at the permission
layer rather than completing account creation. A host that answers the no-op
action with its own 401/403 even for a valid token produces no match — a
conservative false negative, never a false positive.

## Remediation

Update OttoKit (SureTriggers) to 1.1.41 or later, which no longer accepts the
`connection-denied` token. Restrict access to the `wp-json/sure-triggers` REST
routes where feasible.
