# Daptin CVE-2026-77367 unauthenticated entity-list SQL injection

**CVE-2026-77367 is an unauthenticated SQL injection** in Daptin before
0.12.30. The generic `GET /api/<entity>` list handler reads the caller-supplied
`sort` query parameter and passes each entry to `goqu.I()` without checking
that it names a column. `goqu.I()` wraps its argument in the dialect's
identifier quote without escaping an embedded quote of the same kind, so a
backtick (or a double quote on a double-quote dialect) closes the identifier
and the remainder is parsed as SQL. The default `world` entity is
guest-readable, so no credential is needed.

**Affected:** Daptin through 0.12.29
**Fixed:** 0.12.30 (commit `b0bcc13`, which adds `validateSortOrder()`); the
current 0.13.x releases include the fix
**Severity:** CVSS 3.1 9.4 (Critical) — `AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:L/A:H`; CWE-20/CWE-89

`server/resource/resource_findallpaginated.go` had already received this
validation for its fuzzy-search path
([GHSA-rw2c-8rfq-gwfv](https://github.com/daptin/daptin/security/advisories/GHSA-rw2c-8rfq-gwfv)),
but the base `sort` parameter was missed, and it is processed on every list
request to every entity, authenticated or not. The
`world` table and most default tables are readable by a guest, so a default
installation exposes the issue to anyone who can reach the API.

## How does the detector verify the injection?

1. `GET /` must return the Daptin admin landing document with
   `<title>Daptin Admin</title>` and the project marker
   `github.com/daptin/daptin`.
2. `GET /api/world?page[size]=1&sort=id` must return the Daptin entity-list
   JSON:API envelope: an object with a `links` object and a `data` array. This
   proves the entity route is readable and accepts a sort value.
3. `GET /api/world?sort=ostorlab_daptin_probe` sends a plain unknown column.
   A vulnerable build passes it to the database and answers a column error
   (`no such column`, `unknown column`, `does not exist`); a fixed build
   answers `invalid sort column` before the query is built.
4. The detector repeats the request with two values whose embedded quote
   breaks out of the identifier: ``id`x`` and `id"x`. A vulnerable build
   answers a database parse error (`syntax error`, `near "`, `unterminated
   quoted identifier`, `parse error`). A fixed build answers the same
   `invalid sort column` message. The finding requires the parse error to
   differ from the unknown-column error and not to be the fixed message.

The probe reads no row, schema value, file or configuration value and writes
nothing. It only retains the database's own error title for a synthetic value.

## What does a positive finding claim?

The finding confirms that a caller-controlled `sort` value reaches the SQL
identifier unescaped on a Daptin deployment whose default `world` entity is
guest-readable. That is the CVE-2026-77367 injection surface. The finding does
**not** claim that table data was extracted, that a file was read, or that
code was executed; the probe only provokes a parse error. A deployment that
requires authentication for `world` is not probed and produces no finding.

## What does the detector miss?

- It attributes Daptin from the admin landing document. A deployment that
  replaces or removes that dashboard, or blocks `/`, is not attributed.
- It probes only the default `world` entity. A deployment that removes or
  protects `world` is not confirmed even when another entity is exposed; the
  advisory's other default tables are not enumerated.
- It sends two quote shapes. A database dialect that produces a different
  parse-error wording, or a build that transforms the value before the query,
  may not match the syntax markers.
- A reverse proxy that blocks `/api/world` or rewrites the `sort` parameter
  defeats the probe. A proxy that normalizes the quote into an inert
  identifier produces the safe (no-finding) branch.
- The release is not exposed by the unauthenticated landing document, so the
  finding is behavioural: a backported fix that keeps the vendor's validation
  message is not reported, and a later release with the check removed would
  be reported. Network errors, timeouts, redirects, oversized bodies and
  malformed JSON are inconclusive; a missing finding is not proof that the
  deployment is patched.

## How do I reproduce the injection safely?

Replace the host with the Daptin base URL. The requests are anonymous reads;
the quoted values are refused by a fixed build and only produce an error on a
vulnerable one. Do not send a payload that returns rows.

```sh
# Attribution and the benign control.
curl -s 'http://<target>/'
curl -s 'http://<target>/api/world?page[size]=1&sort=id'

# Unknown column: vulnerable -> "no such column: world.ostorlab_daptin_probe"
# fixed -> "table [world] invalid sort column [ostorlab_daptin_probe]"
curl -sG 'http://<target>/api/world' \
  --data-urlencode 'sort=ostorlab_daptin_probe'

# Quote breakout: vulnerable -> "near ... syntax error"
# fixed -> "table [world] invalid sort column [id`x]"
curl -sG 'http://<target>/api/world' --data-urlencode 'sort=id`x'
curl -sG 'http://<target>/api/world' --data-urlencode 'sort=id"x'
```

## How do I remediate CVE-2026-77367?

1. Upgrade Daptin to 0.12.30 or later (the current 0.13.x releases include the
   validation) and restart the service.
2. If an upgrade is not immediately possible, restrict network access to the
   Daptin API and put it behind an authenticating reverse proxy that rejects
   requests carrying quotes, backticks or SQL comments in the `sort`
   parameter.
3. Review HTTP access logs for `sort` values containing quotes, backticks,
   comment markers or SQL keywords while the deployment was exposed.
4. Rotate any credential whose data was reachable by the Daptin database user,
   and review the tables that user can read.

## How do I run this detector?

The detector runs automatically during an `oxo` scan of a responding Daptin
instance; no flag is required. To restrict a scan to this CVE:

```sh
oxo scan run --install --agent agent/ostorlab/asteroid \
  --arg 'custom_cve_list:["CVE-2026-77367"]' url http://<target>
```

To read the agent-side summary, run
`oxo vulnz describe -v CVE-2026-77367`.

## How was the detector validated?

The registered `CVE202677367Exploit` was exercised from a separate network
client against the real upstream `v0.12.29` and `v0.12.28` Linux binaries
(extracted from the published multi-arch images) and the fixed `v0.12.30`
binary, each on its own loopback port with a fresh SQLite database. An
independent stdlib `http.client` oracle that never imports the detector
produced the ground truth; four stdlib lookalikes covered the attribution and
behaviour boundaries.

| Fixture | Oracle (independent) | Detector | Result |
| --- | --- | --- | --- |
| Daptin 0.12.29, SQLite | column error + parse error | 1 finding | TP |
| Daptin 0.12.28, SQLite (variant) | column error + parse error | 1 finding | TP |
| Daptin 0.12.30, SQLite | `invalid sort column` | no finding | TN |
| Daptin-shaped stdlib with fixed validation | `invalid sort column` | no finding | TN |
| Daptin-shaped stdlib treating the quote as a column character | column error only | no finding | TN |
| Other-product stdlib with vulnerable-shaped errors | not attributed | no finding | TN |
| Daptin-titled stdlib whose `/` redirects | not attributed | no finding | TN |

**TP 2 / TN 5 / FP 0 / FN 0 / inconclusive 0** on the real-fixture matrix.
Focused mocked tests cover the fixed validation, the safely quoted branch, a
non-JSON error, a generic unknown-column error, a missing list envelope, a
redirect and an unsupported scheme. Curated fixture results are not a
production false-positive rate.

The detector uses only anonymous HTTP GET requests to the target's own routes,
with a 15 s per-request timeout and bounded response sizes (128 KiB for the
landing document, 64 KiB for the list and 16 KiB for an error).

## Fingerprint

The companion fingerprint is a WhatWeb plugin in `Ostorlab/agent_whatweb`,
`plugins/daptin.rb`, validated with WhatWeb 0.6.4. Both the vulnerable 0.12.29
and the fixed 0.12.30 admin landing documents are identified as **Daptin**; a
page titled `Some Other App` is not. The release is not present in the landing
document, so the plugin extracts no version and component matching cannot
resolve the patch level from it; that is recorded as a gap.

## Generic handoff (not closed by this module)

The reusable pattern — a caller-controlled value concatenated into a SQL
identifier in a generic list/query builder, with the database error reflected
to an unauthenticated caller — is recorded as a handoff to the General Rule
Creator, joining the open SQL-identifier-error and boolean-SQLi handoffs. This
CVE module does not claim generic query-builder coverage.
