# Dockwatch CVE-2026-58455 compose.php command injection

**CVE-2026-58455** is an unauthenticated OS command injection (CWE-698 /
CWE-78) in Dockwatch through 0.6.567. `loader.php` is missing an `exit()`
call after its authentication redirect, so `ajax/compose.php` continues
executing for an unauthenticated caller and passes the `composePath` POST
parameter unsanitized into `shell_exec()`.

**Affected:** Dockwatch through 0.6.567

**Fixed:** a version that adds `exit()` after the redirect and sanitizes
`composePath`

**Severity:** CVSS 3.1 9.8 (Critical) — `AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H`

## How does the detector verify it?

This is an **active, non-destructive, unforgeable** check. It confirms the
product with an anonymous homepage read, then injects a pure shell
arithmetic expression and matches its computed product in the response:

```
GET  /                                                    # confirm Dockwatch
POST /ajax/compose.php
  m=composePull&composePath=x;echo $((<A>*<B>));#
# A, B random per probe; confirm response contains the product A*B
```

Only `echo` is run — no file is read or written, and the two factors are
random per probe, so a server that merely reflects the request body would
contain the literal `$((A*B))` expression, never the computed product. No
credential or cookie is sent and redirects are not followed.

**Limitation:** the check reads the product from whatever the endpoint
echoes back; a vulnerable server that executes the injected command but
discards all output produces no match and is not reported — a conservative
false negative, never a false positive.

## Remediation

Update Dockwatch to a version that adds `exit()` after the authentication
redirect in `loader.php` and sanitizes `composePath`. Restrict network
access to the Dockwatch web UI to trusted clients.
