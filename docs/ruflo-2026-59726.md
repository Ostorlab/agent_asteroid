# CVE-2026-59726: ruflo MCP bridge unauthenticated RCE

**CVE-2026-59726 is an unauthenticated remote code execution** in ruflo before
3.16.3 (CWE-306 / CWE-78 / CWE-942, CVSS 3.1 10.0). The default docker-compose
deployment binds the MCP bridge to all interfaces and exposes `POST /mcp` with
no authentication and no server-side deny list, so an attacker can invoke
`tools/call` for `ruflo__terminal_execute`, which runs attacker input through
`execSync`.

**Affected:** ruflo < 3.16.3 (default docker-compose deployment)

**Fixed:** ruflo 3.16.3 (dangerous-tool gate, bearer auth, loopback bind,
opt-in terminal execution)

**Severity:** CVSS 3.1 10.0 (Critical) — `AV:N/AC:L/PR:N/UI:N/S:C/C:H/I:H/A:H`

## How does the detector verify it?

This is an **active, non-destructive, unforgeable** check. It invokes the
terminal tool with a command that echoes a random arithmetic product, and
confirms that product (never the literal `A*B` expression the request carries)
appears in the response:

```
POST /mcp    Content-Type: application/json
  {"jsonrpc":"2.0","method":"tools/call","id":1,
   "params":{"name":"ruflo__terminal_execute",
             "arguments":{"command":"echo $((<A>*<B>))"}}}
# A, B random per probe; a POSIX shell expands $((A*B)); confirm the product A*B
```

Only `echo` of a pure-arithmetic expansion is run — **no file is read or written
and no persistent command executes**. A server that merely reflects the request
body contains the literal `$((A*B))`, never the product, so a match proves a
shell evaluated it. No credential or cookie is sent and redirects are not
followed.

**Limitation:** the check requires a POSIX shell to expand `$((A*B))`. A
deployment that reaches the tool but runs the command without shell arithmetic
(or returns no output) produces no match and is not reported — a conservative
false negative, never a false positive.

## Remediation

Upgrade ruflo to 3.16.3 or later, which gates dangerous tools in
`executeTool()`, adds bearer-token auth (`MCP_AUTH_TOKEN`), binds to loopback by
default (`BIND_HOST=127.0.0.1`) and makes terminal execution opt-in
(`MCP_ENABLE_TERMINAL`). As interim mitigation, firewall port 3001 and set
`MCP_AUTH_TOKEN` in `docker-compose.yml`.
