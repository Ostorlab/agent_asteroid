# CVE-2026-52715: GEO my WP unauthenticated blind SQL injection

**CVE-2026-52715 is an unauthenticated blind SQL injection** (CWE-89) in the
GEO my WP plugin for WordPress up to and including 4.5.5. The `swlatlng` and
`nelatlng` map-boundary parameters of its locator search form are split on a
comma and concatenated directly into the SQL query without sanitisation.

**Affected:** GEO my WP <= 4.5.5

**Fixed:** a version newer than 4.5.5

**Severity:** CVSS 3.1 9.3 (Critical) — `AV:N/AC:L/PR:N/UI:N/S:C/C:H/I:N/A:L`

## How does the detector verify it?

This is an **active, non-destructive** check using a baseline-vs-`SLEEP` time
differential on the plugin's own read-only locator search:

```
GET /?page_id=4&swlatlng=(SELECT SLEEP(0)),0&nelatlng=1,1    # baseline, fast
GET /?page_id=4&swlatlng=(SELECT SLEEP(6)),0&nelatlng=1,1    # attack, slow
# both responses must carry the plugin's own asset marker;
# attack must take >= 5s longer than the baseline
```

Both requests run only a `SELECT ... SLEEP` subquery through the plugin's
locator search: no row is inserted, updated or deleted, so the probe changes
no state. Requiring the plugin's own CSS/asset marker in both responses guards
against reporting a merely slow server. No credential or cookie is sent and
redirects are not followed.

**Limitation:** the check assumes the plugin's locator search is reachable
from a page with id `4`, matching the public PoC; an install that only exposes
the locator shortcode on a different page id is not reported (a conservative
false negative, never a false positive).

## Remediation

Update GEO my WP to a version newer than 4.5.5, or restrict/disable the
locator search until patched.
