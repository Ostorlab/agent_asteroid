# CVE-2026-110264: GitLab owner-inventory assessment

Evidence checked on 2026-10-29. Coverage remains **offline owner inventory**.
There is no remote detector or `custom_cve_list` registration for this CVE.
The existing inventory dispatcher registers both `GitLab CE` and `GitLab EE`.

## Verified applicability

The [GitLab advisory](https://docs.gitlab.com/releases/patches/patch-release-gitlab-19-5-1-released/)
and [GitLab CNA record](https://cveawg.mitre.org/api/cve/CVE-2026-110264)
agree on CE/EE applicability and CVSS 3.1 10.0
(`AV:N/AC:L/PR:N/UI:N/S:C/C:H/I:H/A:H`). All installation types are in scope.

| Branch/range | Last affected release | Fixed release |
| --- | --- | --- |
| 7.0.0 through 18.11 | 18.11.12 | 18.11.13 |
| 19.0 | 19.0.9 | 19.0.10 |
| 19.1 | 19.1.8 | 19.1.9 |
| 19.2 | 19.2.8 | 19.2.9 |
| 19.3 | 19.3.5 | 19.3.6 |
| 19.4 | 19.4.2 | 19.4.3 |
| 19.5 | 19.5.0 | 19.5.1 |

Earlier-than-7.0 releases, unverified intervening branches such as 18.12,
prereleases, and custom suffixes remain inconclusive. Later stable releases
outside the CNA's affected ranges do not match this version assessment.
GitLab.com is vendor-managed and patched. Dedicated's specifically documented
internal fixed points are `19.3.5-internal0` and `19.4.2-internal0`; later builds
in those two branches are accepted. Other internal branches remain inconclusive.
The generic label `managed` does not identify GitLab-operated infrastructure:
a third-party host can still run an affected self-managed release.

The [Ruby advisory](https://www.ruby-lang.org/en/news/2026/10/23/regexp-fixes-for-gitlab-cves/)
maps this CVE to repeat/null-check ID overflow, distinct from the program-size
overflow fixed for CVE-2026-97229. Ruby 4.0.9, 3.4.12 and 3.3.13 contain the
ID fix; 4.0.8 does not. GitLab backports the fix into its packaged Ruby, so a
bare Ruby version cannot establish GitLab runtime patch provenance.

[Ruby PR #16801 and its regression tests](https://github.com/ruby/ruby/pull/16801/files)
add bounds checks for both ID counters and require oversized generated patterns
to raise compilation errors. [GitLab's packaging patch](https://gitlab.com/gitlab-org/omnibus-gitlab/-/merge_requests/9921)
and [19.5 backport](https://gitlab.com/gitlab-org/omnibus-gitlab/-/merge_requests/9922)
confirm that these checks prevent signed 16-bit ID wrap and the subsequent
match-time out-of-bounds write. No regression trigger is executed by this assessor.

## Evidence contract

Use `python -m agent.utils.inventory inventory.json` with an array of owner-verified
records for the same running target. This is Asteroid's schema, not a vendor API.

```json
[
  {
    "product": "GitLab EE",
    "version": "19.4.2-ee.0",
    "deployment": "self-managed",
    "ruby_repeat_id_fix_applied": false,
    "ruby_patch_evidence": "Owner reviewed build manifest and patch provenance for the active GitLab Ruby; neither ID check is present.",
    "untrusted_org_rendering_reachable": true
  }
]
```

- `product`, `version`, and `deployment` identify the running GitLab. Canonical
  three-component releases and matching `-ce`, `-ee`, `-ce.0`, `-ee.0` suffixes
  are supported. Dedicated internal suffixes are accepted only for Dedicated EE.
- Optional `ruby_repeat_id_fix_applied` is a JSON boolean. `true` attests that
  **both** upstream ID checks are deployed in the Ruby actually running GitLab;
  `false` attests their absence. Either requires nonempty `ruby_patch_evidence`
  identifying the inspected runtime/build and patch provenance. Inspect trusted
  package/build records and their correspondence to running workers, including
  source installations and custom runtimes. An unrelated system Ruby, downloaded
  patch, old process inventory, or Ruby version alone is insufficient evidence.
  Omit both fields (or supply nulls) when unknown. This code validates field
  shape, not the truth or completeness of an owner's attestation.
- Optional `untrusted_org_rendering_reachable` is a boolean or null. It describes
  whether attacker-controlled Org-mode input reaches the running markup renderer.
  Generic feature presence or a public project alone does not establish this.
  Missing/null means unknown. False does not prove every possible path absent.

An affected release returns `potential_exposure`, with the known path's reported
state and exploitability explicitly unconfirmed. Verified-owner patch claims
return `not_matched`, including backports below a normal fixed release. Fixed
release or managed-service evidence contradicted by an unpatched runtime claim
returns `inconclusive`. Malformed/partial patch attestations cannot clear a
finding. Evidence text and arbitrary record fields are never echoed by the CLI.
`not_matched` only describes this evidence assessment; it is not a safety verdict.

## Remote-coverage gap

The starting [Ostorlab blog](https://blog.ostorlab.co/gitlab-unauthenticated-rce-cve-2026-110264.html)
describes undisclosed preconditions. The current vendor
[Org-mode rule](https://gitlab.com/gitlab-security-oss/tldr/-/raw/main/Detections/platforms/GitLab/Vulnerability%20Detections/org_mode_render_error_burst.md)
adds a concrete input path through custom TODO keywords and the markup renderer.
Its timeout/preview telemetry is for investigating attempts, not a benign
vulnerability oracle. The companion
[native-crash rule](https://gitlab.com/gitlab-security-oss/tldr/-/raw/main/Detections/platforms/GitLab/Vulnerability%20Detections/onigmo_native_worker_crash.md)
explicitly warns that a successful exploit can be quiet and crash absence does
not establish safety. Neither a timeout nor a crash uniquely confirms this CVE.

No verified non-destructive remote discriminator was found. Benign rendering
would only establish feature behavior; exercising the ID boundary risks memory
corruption or resource exhaustion. The HackerOne report returned HTTP 403 and
the linked GitLab work item did not disclose its technical contents during this
review. No requests, regex payloads, project/file changes, or target commands are
performed by this implementation. Revisit remote coverage only with a documented
safe discriminator and controls that distinguish this flaw from ordinary errors.
