# Next.js CVE-2025-29927 middleware authorization bypass

Next.js 11.1.4 through 15.2.2 lets an attacker bypass middleware (and the authorization it enforces) by sending the internal `x-middleware-subrequest` header (CWE-285).

## References
- NVD: <https://nvd.nist.gov/vuln/detail/CVE-2025-29927> (published 2025-03-21 by the GitHub CNA, CVSS 3.1 9.1).
- Fix commit: <https://github.com/vercel/next.js/commit/52a078da3884efe6501613c7834a3d02a91676d2>.
- CVE record: <https://www.cve.org/CVERecord?id=CVE-2025-29927>.

## Affected and fixed versions
Next.js **11.1.4 through 15.2.2**; fixed in 15.2.3 / 14.2.25 / 13.5.9 / 12.3.5.

## How the detection confirms it
A baseline request must return a 307 middleware rewrite (middleware active), then the same request with `x-middleware-subrequest` must return the protected page (200) with no WAF rejection. Only the page is read.

The header cannot be sent through the anonymous `defensive_http` transport, so the scanner session is used directly.

## Remediation
Upgrade Next.js and do not rely solely on middleware for authorization.
