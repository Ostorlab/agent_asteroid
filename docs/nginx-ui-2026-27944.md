# Nginx UI CVE-2026-27944 unauthenticated backup download

**CVE-2026-27944** lets anyone download a full, decryptable backup from
[Nginx UI](https://github.com/0xJacky/nginx-ui) before **2.3.3**. The backup
route had no authentication middleware (CWE-306), and the response carries the
backup's AES-256 key and IV in a header (CWE-311):

```go
// api/backup/router.go, v2.3.2
r.GET("/backup", CreateBackup)

// api/backup/backup.go
c.Header("X-Backup-Security", securityToken) // base64 key ":" base64 iv
```

The backup holds the Nginx UI database (user credentials, session tokens),
`app.ini` secrets, the nginx configuration and TLS private keys.

  (<https://github.com/0xJacky/nginx-ui/security/advisories/GHSA-g9w5-qffc-6762>),
  credited to Tenable (<https://www.tenable.com/security/research/tra-2026-17>).

## Affected and fixed versions

All releases before **2.3.3** are affected. 2.3.3 (GitHub release published
2026-02-15) contains the fix commit.

## How the detection confirms it

1. **Attribution** — `GET /api/upgrade/current` is a public route that returns
   `internal/version.Info` as JSON (`version`, `build_id`, `total_build`,
   `short_hash`). The host is accepted only when `version` is a string,
   `build_id` an integer and `short_hash` a string. The read is capped at 4 KB.
2. **Version gate** — when the advertised version is 2.3.3 or later the backup
   route is **not requested at all**, so patched hosts are never asked to build
   a backup.
3. **Evidence** — `GET /api/backup`. A finding needs HTTP 200, a
   `application/zip` content type, an `attachment` content disposition and a
   non-empty `X-Backup-Security` header. The decision uses headers only: the
   backup body is never read, and the key value is never stored or put in the
   finding.

The server builds the backup in a temporary directory that it removes itself
(`defer os.RemoveAll(tempDir)` in `internal/backup/backup.go`), so the request
leaves no state behind. No credential or cookie is sent and redirects are not
followed. A host behind Nginx UI's IP allow-list answers 403 and is not
reported.

## Remediation

Upgrade Nginx UI to 2.3.3 or later. Until then, keep its port off the internet
or set the IP allow-list, and block `/api/backup` at the reverse proxy. Treat
the backup as disclosed: rotate Nginx UI user passwords and the JWT secret,
replace the TLS private keys and certificates served by nginx, and review
access logs for anonymous requests to `/api/backup`.
