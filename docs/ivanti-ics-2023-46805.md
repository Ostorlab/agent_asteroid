# Ivanti Connect Secure authentication bypass (CVE-2023-46805)

**CVE-2023-46805** is an authentication-bypass vulnerability in the web
component of Ivanti Connect Secure (9.x, 22.x) and Ivanti Policy Secure
(CWE-287). An allow-listed API prefix can be followed by a literal `../..`
traversal that reaches an otherwise-authenticated endpoint, so an anonymous
client reads restricted system and configuration data. It was chained with
CVE-2024-21887 (command injection) in the wild.

```text
GET /api/v1/totp/user-backup-code/../../system/system-information
```

## References
- NVD: <https://nvd.nist.gov/vuln/detail/CVE-2023-46805> (published 2024-01-12, CWE-287, CVSS 3.1 8.2).
- Ivanti advisory: <https://forums.ivanti.com/s/article/CVE-2023-46805-Authentication-Bypass-CVE-2024-21887-Command-Injection-for-Ivanti-Connect-Secure-and-Ivanti-Policy-Secure-Gateways>.
- CVE record: <https://www.cve.org/CVERecord?id=CVE-2023-46805>.

## Affected versions
Ivanti Connect Secure **9.x and 22.x** and Ivanti Policy Secure. Apply the
vendor mitigation and patched builds from the advisory.

## How the detection confirms it
Anonymous `GET` requests send the literal `../..` traversal on the wire (the
reader restores the raw path so `requests` does not collapse the dot segments).
A finding needs HTTP 200, a JSON content type, and the restricted endpoint's own
markers -- `build` / `system-information` / `software-inventory`, or
`poll_interval": 300` / `block_message": ""` for the admin-options variant.
Only read-only endpoints are requested; the probe changes no state.

## Remediation
Apply the Ivanti patches referenced in the advisory, run the Integrity Checker
Tool, and treat an exposed appliance as potentially compromised.
