# N-able N-central CVE-2026-86206 ACL filter bypass

**CVE-2026-86206** is an improper check for unusual conditions (CWE-791) in
N-able N-central's internal API access-control filter. A path-matrix segment
in `/dms;/services/ServerUI` combined with a spoofed `Forwarded` header
claiming a loopback caller confuses the filter, letting a remote,
unauthenticated caller reach the internal SOAP API.

**Affected:** N-central versions before 2026.3 HF3 / 2026.4

**Fixed:** N-central 2026.3 HF3 and 2026.4

**Severity:** CVSS 4.0 6.9 (Medium) —
`AV:N/AC:L/AT:N/PR:N/UI:N/VC:L/VI:N/VA:N/SC:N/SI:N/SA:N`. NVD rates this
confidentiality-only and Medium; the nuclei template tags it critical, but
the NVD score is authoritative and is kept here.

## How does the detector verify it?

This is an **active, non-destructive, differential** check. A baseline SOAP
`sessionHello` call with no `Forwarded` header must be refused, and only an
otherwise identical call carrying the spoofed header may return a
`SessionID`:

```
POST /dms;/services/ServerUI                              # baseline: refused
POST /dms;/services/ServerUI
Forwarded: for="127.0.0.1"                                 # bypass: SessionID returned
```

Requiring the baseline to be refused rules out a deployment where the
internal API is reachable regardless of the header; only a target where the
spoofed loopback origin flips the outcome is reported. Both calls are single
bounded reads of the same internal introspection call — no data is written
and redirects are not followed.

## Remediation

Update N-central to 2026.3 HF3 or 2026.4 or later. Restrict network access to
the N-central internal API to trusted callers.
