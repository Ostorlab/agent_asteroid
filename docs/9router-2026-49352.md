# 9Router CVE-2026-49352 hardcoded fallback JWT secret auth bypass

**CVE-2026-49352** is a hardcoded-credential authentication bypass in 9Router
(CWE-798). 9Router 0.2.21 through 0.4.43 falls back to the hardcoded secret
`9router-default-secret-change-me` in its authentication components when
`JWT_SECRET` is unset, letting an attacker forge an `auth_token` cookie
offline and reach protected pages without credentials.

**Affected:** 9Router 0.2.21 up to and including 0.4.43 (with `JWT_SECRET`
unset)

**Fixed:** 0.4.44

**Severity:** CVSS 3.1 9.8 (Critical) — `AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H`

## How does the detector verify it?

```
GET /dashboard
Cookie: auth_token=<HS256 JWT signed with "9router-default-secret-change-me">
```

The probe forges an HS256 token with a far-future expiry, signed with the
publicly documented hardcoded fallback secret, and presents it as the
`auth_token` cookie on the protected dashboard route. A finding requires HTTP
200 with the dashboard page markers present and the login page markers
absent, proving the server accepted a signature it never issued. The forged
cookie is sent via an isolated prepared request so no other session state is
carried; no mutation is sent and redirects are not followed.

**Limitation:** this confirms only that the hardcoded fallback secret is
still accepted; it cannot distinguish an instance where `JWT_SECRET` was set
to the same literal default value by an operator (functionally identical
exposure) from one where it was simply left unset.

## Remediation

Upgrade 9Router past 0.4.43 (to 0.4.44 or later) and set a strong, unique
`JWT_SECRET`.
Rotate the secret and invalidate existing sessions after upgrading.
