# Arize Phoenix CVE-2026-53998 applyChatTemplate format-string injection

**CVE-2026-53998 is an unauthenticated format-string injection** in the Arize
Phoenix AI observability platform. From 13.0.0 through before 15.7.0, the
`applyChatTemplate` GraphQL query passed caller-supplied F-string message text
to `FStringTemplateFormatter._format` and then `str.format`, while the
`DotDict` wrapper did not block access to private attributes.

**Affected:** arize-phoenix 13.0.0 through before 15.7.0
**Fixed:** 15.7.0 (commit `e7224a6`)
**Severity:** CVSS 3.1 10.0 (Critical) — `AV:N/AC:L/PR:N/UI:N/S:C/C:H/I:H/A:L`; CWE-134 and CWE-200

A template such as
`{u.__class__.__init__.__globals__[_os].environ}` walks from a supplied value
into the formatter module and returns the process environment, including
`PHOENIX_SECRET`. That secret signs administrative session tokens and derives
the Fernet key protecting stored provider and OAuth credentials. The endpoint
is reachable without credentials on a default installation, and by any account
when authentication is enabled. The GitHub advisory contains a working payload.

## How does the detector verify the injection?

1. `GET /arize_phoenix_version` must return a plain-text release such as
   `15.4.0`. This is Phoenix's public version document.
2. The release must be in the affected range, from 13.0.0 up to but excluding
   15.7.0. A release outside the range stops here.
3. `POST /graphql` sends the anonymous `applyChatTemplate` query with one
   `USER` message whose text is `ostorlab-phoenix-probe-{u.__class__.__name__}`
   and the variable `u` set to a fixed string. The response must be HTTP 200
   JSON with `data.applyChatTemplate.messages` and a text part equal to
   `ostorlab-phoenix-probe-str`.

That exact rendered value proves the server evaluated the private
`__class__.__name__` attribute on the supplied string. A literal renderer
echoes the braces and never matches; a GraphQL lookalike without the field
returns an error; an authentication-protected endpoint answers 401.

A fixed 15.7.0 server installs a formatter that rejects any attribute starting
with an underscore and answers with
`Access to attribute '__class__' is not permitted in templates`; an affected
release with that backport is not reported.

The probe reads no environment variable, secret, private module state or
database value. It sends only anonymous metadata GET/POST requests with no
credential, cookie, session or mutation. The advisory's `os.environ` read,
`PHOENIX_SECRET` disclosure, session forgery and credential decryption are
**not** exercised or claimed.

## What does a positive finding claim?

The finding confirms that an anonymous `applyChatTemplate` query made Phoenix
evaluate a private attribute of a caller-supplied value, which is the
format-string injection primitive behind CVE-2026-53998. It does not claim that
`PHOENIX_SECRET`, another environment variable, or stored credentials were
read. A fixed 15.7.0 server, a backported safe formatter, or a deployment that
requires authentication for the GraphQL query is not reported.

## What does the detector miss?

- A deployment that removes or renames `/arize_phoenix_version` is not
  attributed, even when the GraphQL endpoint is reachable.
- A deployment mounted under a path prefix (for example a proxy serving
  Phoenix at `/phoenix`) is not probed, because the standard paths are not
  rewritten.
- A reverse proxy that blocks `/graphql`, or an authentication layer that
  answers 401/403 for the query, is not reported; the anonymous exposure is
  what the CVE describes.
- A release string that is not a plain `X.Y.Z` release (for example a custom
  build suffix that `packaging.version` cannot parse) is not probed.
- Network errors, timeouts, redirects, oversized bodies and malformed JSON are
  inconclusive; a missing finding is not proof that the endpoint is patched.

## How to reproduce and remediate

Read the version and submit the evaluation probe yourself:

```sh
# 1. Phoenix release.
curl -sS 'http://<target>/arize_phoenix_version'

# 2. Template evaluation (no environment or secret is read).
curl -sS -X POST 'http://<target>/graphql' \
  -H 'Content-Type: application/json' \
  --data '{
    "query": "query ($template: PromptChatTemplateInput!, $templateOptions: PromptTemplateOptions!) { applyChatTemplate(template: $template, templateOptions: $templateOptions) { messages { role content { ... on TextContentPart { text { text } } } } } }",
    "variables": {
      "template": {"messages": [{"role": "USER", "content": [{"text": {"text": "ostorlab-phoenix-probe-{u.__class__.__name__}"}}]}]},
      "templateOptions": {"format": "F_STRING", "variables": {"u": "ostorlab-probe-value"}}
    }
  }'
```

A vulnerable server returns
`{"data":{"applyChatTemplate":{"messages":[{"role":"USER","content":[{"text":{"text":"ostorlab-phoenix-probe-str"}}]}]}}}`.
A fixed 15.7.0 server returns a GraphQL `errors` array with
`Access to attribute '__class__' is not permitted in templates`.

Upgrade to arize-phoenix 15.7.0 or later. If an earlier build was reachable,
rotate `PHOENIX_SECRET` and every credential or token stored in Phoenix,
invalidate existing sessions, and review GraphQL logs for
`applyChatTemplate` requests containing underscore attribute names. Enable
authentication and restrict `/graphql` when it is not needed anonymously. For
the agent-side summary, run `oxo vulnz describe -v CVE-2026-53998`.

## How do I run this detector?

The detector runs automatically during an `oxo` scan of a responding Phoenix
instance; no flag is required. To restrict a scan to this CVE:

```sh
oxo scan run --install --agent agent/ostorlab/asteroid \
  --arg 'custom_cve_list:["CVE-2026-53998"]' url http://<target>
```

## Validation

The registered `CVE202653998Exploit` was exercised from a separate network
client against real PyPI releases on loopback, with an independent stdlib
`http.client` oracle that never imports the detector:

| Fixture | Oracle | Detector | Result |
| --- | --- | --- | --- |
| arize-phoenix 15.4.0 (vulnerable, real release) | rendered `ostorlab-phoenix-probe-str` | 1 finding | TP |
| arize-phoenix 14.17.0 (vulnerable variant) | rendered `ostorlab-phoenix-probe-str` | 1 finding | TP |
| arize-phoenix 15.7.0 (fixed) | `Access to attribute '__class__' is not permitted in templates` | no finding | TN |
| arize-phoenix 15.4.0 with authentication enabled | HTTP 401 on `/graphql` | no finding | TN |
| literal renderer lookalike (`15.4.0`, braces echoed) | marker not evaluated | no finding | TN |
| GraphQL lookalike (`15.4.0`, no `applyChatTemplate` field) | field error | no finding | TN |
| version-only lookalike (`15.4.0`, `/graphql` 404) | no query response | no finding | TN |
| protected simulacrum (`15.4.0`, 401) | 401 | no finding | TN |
| non-Phoenix version document with a rendered marker | behavior present, product attribution absent | no finding | TN |

**TP 2 / TN 7 / FP 0 / FN 0 / inconclusive 0** on the real-fixture matrix.
The focused mocked suite covers a fixed error, a literal renderer, a missing
version document, a non-release version body, a protected endpoint, non-JSON
answers, a missing GraphQL field, malformed JSON, an unsupported scheme and a
direct `check()` call on a lookalike. Curated fixture results are not a
production false-positive rate.

## Generic handoff (not closed by this module)

The reusable pattern — an unauthenticated template-rendering API that evaluates
caller-controlled expressions and permits private-attribute traversal into
process state — is recorded as a handoff to the General Rule Creator. This CVE
module does not claim generic server-side template injection coverage.
