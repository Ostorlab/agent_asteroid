# PHP-CGI CVE-2012-1823 argument injection remote code execution

**CVE-2012-1823** is a remote code execution flaw in PHP run as a CGI
(`php-cgi`). `sapi/cgi/cgi_main.c` before PHP 5.3.12 and 5.4.x before 5.4.2
does not skip `php_getopt` when the query string contains no unencoded `=`, so
an anonymous request can pass `-d` options straight to the interpreter
(CWE-77).

```text
POST /?-d+allow_url_include%3d1+-d+auto_prepend_file%3dphp://input
Content-Type: application/x-www-form-urlencoded

<?php echo 1234*5678;?>
```

`-d allow_url_include=1` and `-d auto_prepend_file=php://input` make php-cgi run
the request body as PHP.

## Affected and fixed versions

PHP before **5.3.12** and 5.4.x before **5.4.2** when deployed as php-cgi. Both
fixed releases are from May 2012.

## How the detection confirms it, safely

One anonymous `POST /` carrying the injection query and a body of
`<?php echo A*B;?>`, where `A` and `B` are two random integers between 1000 and
9999 chosen for that single request. The host is reported only when the
response contains the product `A*B` **and** does not contain the literal
payload. Because the product is computed from random factors and never sent in
the request, a server that merely echoes the body cannot match — php-cgi must
have executed the code.

The payload prints one number: it reads no file, writes nothing, sends no
credential or cookie and follows no redirect. The response is byte-capped. The
probe is sent to `/` only, so php-cgi behind a custom `ScriptAlias` may be
missed.

## Remediation

Upgrade PHP to 5.4.2 / 5.3.12 or later, or move from php-cgi to PHP-FPM or
mod_php. If php-cgi must stay, apply the vendor patch and make sure the web
server does not hand the raw query string to the php-cgi binary. Because this
allows unauthenticated code execution (and is in the CISA KEV catalog), review
the host for web shells, unexpected cron jobs and new accounts, and rotate any
secrets the web process can read.
