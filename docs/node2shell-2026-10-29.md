# CVE-2026-111497: evidence and coverage, 29 October 2026

This remote scanner check reports **potential Node.js version exposure**, not
confirmed exploitability. It obtains HTTP headers directly from the supplied
target. It sends no compressed input and executes no target code. There are no
new offline inventory assessments in this change.

## Verified semantics

The [Ostorlab article](https://blog.ostorlab.co/node2shell-brotli-rce-cve-2026-111497.html)
was the research starting point. The implementation follows the sources below:

- [Node.js advisory](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases)
  describes an invalid block switch being mistaken for a need for more input,
  leading to an out-of-bounds write. Attacker-controlled data must reach a Brotli
  decoder; a Node HTTP server or Express banner alone does not establish this.
- The [Brotli fix](https://github.com/google/brotli/commit/0ed4268a4401abcb4472096340477cf4af7d1a2b)
  distinguishes a permanent block-switch error from incomplete input and checks
  the status in both decoding paths. It changes decoder error handling, not an
  HTTP response contract.
- [Node's regression change](https://github.com/nodejs/node/commit/0392385841)
  tests both synchronous decoding and byte-at-a-time streaming. The expected
  patched error is `ERR__ERROR_FORMAT_BLOCK_SWITCH`, errno `-17`. This is a
  local decoder regression test, not a guarantee that sending that malformed
  stream to an arbitrary application is harmless.
- Official fixed releases are [22.23.4](https://nodejs.org/en/blog/release/v22.23.4),
  [24.22.1](https://nodejs.org/en/blog/release/v24.22.1), and
  [26.12.1](https://nodejs.org/en/blog/release/v26.12.1). The latter's
  [Brotli version header](https://github.com/nodejs/node/blob/v26.12.1/deps/brotli/c/common/version.h)
  still says 1.2.0: the patch was backported. A library version alone cannot
  establish that a deployed decoder lacks the fix.
- Node rates the flaw High; the [Envoy advisory](https://github.com/envoyproxy/envoy/security/advisories/GHSA-3wvj-j6qm-62mr)
  rates the underlying CVE Critical (CVSS v4 9.2). This passive finding uses
  **HIGH**, matching Node's severity label, at the emitted report level. Severity
  is not proof of exploitability: its short description and technical evidence
  explicitly qualify the result. The historical finding title is retained.

## Remote Node evidence

The accept step selects HTTP/HTTPS without network I/O. The check step makes
one anonymous, streamed GET to the supplied path
(or `/` when absent), using the existing `defensive_http` helper. It reads only
headers, closes responses, does not follow redirects, and sends no session
credentials, cookies, request body, or content-encoding header.

A successful response must advertise one canonical, unambiguous Node.js version
in `Server` and/or `X-Powered-By`. The finding records the observed version and
header names. Conflicting versions, partial versions, custom/prerelease suffixes,
comments, URLs, non-success responses, generic Express headers, and Brotli library banners do
not produce findings. Supported Node branches are 22, 24, and 26 only.

The old three-POST differential was removed. Its 2xx/400 status pattern and
`BLOCK_LENGTH` substring cannot prove which decoder processed the data, that
Brotli decoding occurred, or that the application lacks the fix. Replaying a
malformed decoder regression on arbitrary services also lacks a demonstrated
non-destructive guarantee. Error strings and HTTP status alone are therefore
not an exploitability oracle. No replacement malformed stream was invented.

An empty finding list does not mean patched. A positive banner match still
requires verification of the running binary, backports, linked libraries, and
untrusted Brotli reachability. The finding is not a proof of remote execution.

## Remote false-positive verification

The checked-in response corpus is
`tests/fixtures/cve_2026_111497_remote_fp.json`. It contains 32 known-negative
static-response scenarios, three synthetic affected-version header controls,
and eight unknown-evidence cases. Negative cases include all three fixed
boundaries, absent/product-only banners, authentication failures, redirects,
proxy/WAF responses, incompatible versions, comments/URLs, suffixes, and six
intentional valid-format spoofed/stale Node banners. Unknown cases include
unresearched branches and malformed/conflicting metadata.

The three positive controls use advisory-affected 22.23.3, 24.22.0 and 26.12.0
headers. They test preservation of the version signal, not a running vulnerable
decoder. No representative production corpus or live vulnerable/patched product
pair is available; no production FP rate can be established.

Potential-exposure alerts count as positives. The remote API has no definitive
negative verdict: an empty finding list is an abstention. Observed mocked-corpus
results after correction: 32 known negatives produce 6 potential false alerts,
0 definitive true negatives, and 26 abstentions; 3/3 positive header controls
are detected (0 missed, 0 inconclusive); all 8 unknown cases abstain. No confirmed
vulnerability alerts are emitted. On the decisive negative subset the formal
FPR is 6/(6+0) = 100%, with only 6/32 negative cases classified. This selective
rate is not a production estimate. The false-alert fraction across all negative
fixtures is 6/32 (18.75%); that fraction includes abstentions and is not FPR.

The baseline parser produced 10 alerts on these same 32 negative header
fixtures. Four incorrect product matches in comments, URLs and nested product
names were removed. The remaining six cannot be distinguished from truthful
banners by passive headers alone; this limitation is deliberately retained in
the corpus, rather than hidden by claiming zero observed FPs.

The local replay test serves the same negative responses from a static Python
HTTP handler bound only to 127.0.0.1, with no Node process or Brotli decode path.
It checks actual transport behavior and spoofing risk without sending payloads
to public targets. These are repeat observations of the same cases, not 32
additional independent samples. Run the corpus checks with:

```shell
python -m pytest -q -s tests/exploits/cve_2026_111497_test.py -k FalsePositiveCorpus
```

The remote-only change preserves the pre-existing Envoy block and shared
inventory/README files byte-for-byte from the PR base. No new offline schema,
dispatch registrations or inventory-only tests remain.
