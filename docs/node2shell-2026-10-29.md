# CVE-2026-111497: evidence and coverage, 29 October 2026

This assessment covers the Brotli decoder flaw, not every possible deployment
of Brotli. It never sends compressed input or executes target code. Runtime and
proxy applicability below is an offline owner-inventory assessment. Only Node.js
has a remote check, and that check reports **potential exposure**, not confirmed
exploitability.

## Verified semantics

The [Ostorlab article](https://blog.ostorlab.co/node2shell-brotli-rce-cve-2026-111497.html)
was the research starting point. The implementation follows the sources below:

- [Node.js advisory](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases)
  describes an invalid block switch being mistaken for a need for more input,
  leading to an out-of-bounds write. Attacker-controlled data must reach a Brotli
  decoder; a Node HTTP server or Express banner alone does not establish this.
- The [Brotli fix](https://github.com/google/brotli/commit/0ed4268a4401abcb4472096340477cf4af7d1a2b)
  distinguishes a permanent block-switch error from incomplete input and checks
  the status in both decoding paths. It changes decoder error handling, not an
  HTTP response contract.
- [Node's regression change](https://github.com/nodejs/node/commit/0392385841)
  tests both synchronous decoding and byte-at-a-time streaming. The expected
  patched error is `ERR__ERROR_FORMAT_BLOCK_SWITCH`, errno `-17`. This is a
  local decoder regression test, not a guarantee that sending that malformed
  stream to an arbitrary application is harmless.
- Official fixed releases are [22.23.4](https://nodejs.org/en/blog/release/v22.23.4),
  [24.22.1](https://nodejs.org/en/blog/release/v24.22.1), and
  [26.12.1](https://nodejs.org/en/blog/release/v26.12.1). The latter's
  [Brotli version header](https://github.com/nodejs/node/blob/v26.12.1/deps/brotli/c/common/version.h)
  still says 1.2.0: the patch was backported. A library version alone cannot
  establish that a deployed decoder lacks the fix.
- Node rates the flaw High; the [Envoy advisory](https://github.com/envoyproxy/envoy/security/advisories/GHSA-3wvj-j6qm-62mr)
  rates the underlying CVE Critical (CVSS v4 9.2). The existing CVE severity and
  finding title are retained for compatibility; the short description and
  technical evidence explicitly qualify the result.

## Remote Node evidence

The registered detector makes an anonymous, streamed GET to the supplied path
(or `/` when absent), using the existing `defensive_http` helper. It reads only
headers, closes responses, does not follow redirects, and sends no session
credentials, cookies, request body, or content-encoding header.

A successful response must advertise one canonical, unambiguous Node.js version
in `Server` and/or `X-Powered-By`. The finding records the observed version and
header names. Conflicting versions, partial versions, custom/prerelease suffixes,
non-success responses, generic Express headers, and Brotli library banners do
not produce findings. Supported Node branches are 22, 24, and 26 only.

The old three-POST differential was removed. Its 2xx/400 status pattern and
`BLOCK_LENGTH` substring cannot prove which decoder processed the data, that
Brotli decoding occurred, or that the application lacks the fix. Replaying a
malformed decoder regression on arbitrary services also lacks a demonstrated
non-destructive guarantee. Error strings and HTTP status alone are therefore
not an exploitability oracle. No replacement malformed stream was invented.

An empty finding list does not mean patched. A positive banner match still
requires verification of the running binary, backports, linked libraries, and
untrusted Brotli reachability. The finding is not a proof of remote execution.

owner records. The CLI does not discover inventory, authenticate evidence, or

All prerequisite fields are actual JSON booleans. Missing fields, strings such
as `"true"`, and numeric `1` are inconclusive. For runtimes/packages,
`official_build: true` attests that the deployed artifact uses the official
bundled decoder, with no vendor backport, system-library substitution, or custom
build. If that cannot be verified, leave it unknown or false for an inconclusive
result. For proxies, the canonical release and effective decompressor
configuration use the existing owner-evidence contract; custom builds require
separate vendor verification.

`untrusted_brotli_input: true` means owner evidence establishes a route that
actually decompresses untrusted Brotli, whether an incoming request, outgoing
HTTP response, or explicit API call. Merely installing a Python package,
advertising `br`, enabling response compression, or running ASP.NET Core does
not meet this condition. A false prerequisite means this assessment does not
match the supplied configuration. Matching affected releases with verified
prerequisites produce `potential_exposure`, with exploitability unconfirmed.

## Downstream sources and deliberate limits

- Bun's tagged dependency definitions for [1.4.3](https://github.com/oven-sh/bun/blob/bun-v1.4.3/scripts/build/deps/brotli.ts)
  and [1.4.4](https://github.com/oven-sh/bun/blob/bun-v1.4.4/scripts/build/deps/brotli.ts)
  pin Brotli 1.2.0 and 1.2.1 respectively. Older Bun releases were not traced
  individually and remain inconclusive; no blanket "all older Bun" claim.
- The [Python advisory](https://github.com/advisories/GHSA-9v8h-qqgm-4m35),
  [Brotli package index](https://pypi.org/pypi/Brotli/json), and
  [brotlicffi package index](https://pypi.org/pypi/brotlicffi/json) establish the
  published package versions used here. Native C backports 1.0.10/1.1.1 are not
  published PyPI package versions and are not silently classified as affected.
- [Microsoft's advisory](https://github.com/dotnet/announcements/issues/494)
  requires explicitly enabled/requested Brotli decompression. .NET Framework is
  unaffected. The implementation covers stable 8/9/10 runtimes; .NET 11
  preview/RC versions remain inconclusive and must be checked against the
  advisory (fixed RC: 11.0.0-rc.3.26522.148). Self-contained/NativeAOT artifacts
  must be rebuilt; a patched machine-wide runtime is not sufficient evidence.
- [Envoy's advisory](https://github.com/envoyproxy/envoy/security/advisories/GHSA-3wvj-j6qm-62mr)
  lists four exact affected releases and requires a configured Brotli
  decompressor. Earlier releases are not automatically inferred affected.
- [Istio's advisory](https://istio.io/latest/news/security/istio-security-2026-007/)
  identifies the three assessed branches and the Brotli decompression condition.
  Other branches remain inconclusive.

The two requested local branches were inspected read-only:
`fix/node2shell-differential-and-banner-evidence` at `6708541` has the same
Node2Shell detector as the audit baseline; `fix/brotli-detection-evidence` at
`b43c71c` supplied the passive-check approach and regression test foundation.
No commits were cherry-picked and neither branch was modified. Shared inventory
dispatch receives only six additive product registrations.
