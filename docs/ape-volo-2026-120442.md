# CVE-2026-120442: ape-volo-admin hardcoded JWT key authentication bypass

**CVE-2026-120442 is an authentication bypass** in ape-volo-admin (CWE-1394,
CVSS 3.1 9.8). The application ships a hardcoded JWT signing key in
`appsettings.json`, so an attacker can sign an administrator token offline (the
`jti` claim set to the seeded administrator id) and reach the protected API
without any credentials, gaining full control of users, roles and data.

**Affected:** ape-volo-admin before 3.6.1

**Fixed:** ape-volo-admin 3.6.1 or later

**Severity:** CVSS 3.1 9.8 (Critical) — `AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H`

## How does the detector verify it?

This is an **active, non-destructive** check. It presents the publicly
documented forged administrator token (signed with the leaked key, `exp` set to
year 2100) to the read-only user listing and confirms the paginated collection
is returned:

```
GET /user/query?pageSize=1&pageIndex=1
  Authorization: Bearer <forged-admin-token-signed-with-hardcoded-key>
  Accept: application/json
# confirm: HTTP 200, body contains "content":[ AND "totalElements": AND "totalPages":
```

The forged token carries no secret and grants nothing by itself: a patched
server (3.6.1+) that rotated the signing key rejects the signature and answers
`401`, so no user collection is returned. Observing the paginated user list for
a request authenticated only by a token signed with the publicly known key
proves the server still trusts that key. The forged `Authorization` header is
sent on an isolated prepared request (never `Session.prepare_request`), so no
scanner cookie or auth is merged; only the first user-list page is read
(bounded to 64 KiB) and no redirect is followed.

**Limitation:** an instance that has rotated the signing key but not upgraded,
or that exposes the API under a different base path, is not reported (a
conservative false negative, never a false positive).

## Remediation

Upgrade ape-volo-admin to 3.6.1 or later and replace the JWT signing key in
`appsettings.json` with a unique secret. Restrict network access to the admin
API to trusted clients.
