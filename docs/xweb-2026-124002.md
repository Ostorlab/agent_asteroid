# CVE-2026-124002: Copeland/Dixell XWEB EVO pre-auth OS command injection

**CVE-2026-124002 is a pre-authentication OS command injection** in Copeland/
Dixell XWEB EVO (CWE-78, CVSS 3.1 9.8). `GET /cgi-bin/login.lua` splices the
submitted `username` directly into an `io.popen()` shell command (a `find`
invocation) before any password check, so a username carrying shell
metacharacters executes arbitrary OS commands as `www-data`.

**Affected:** XWEB EVO 5.2.3 through before 5.7.0

**Fixed:** 5.7.0 (the product is End-of-Software-Support; no further patches)

**Severity:** CVSS 3.1 9.8 (Critical) — `AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H`

## How does the detector verify it?

This is an **active, non-destructive, unforgeable** check. It injects an `echo`
of a random arithmetic expansion wrapped in a random marker into the `username`
parameter and confirms the computed product (never the literal `A*B` expression
the request carries) appears in the response wrapped in that same marker:

```
GET /cgi-bin/login.lua?action=login&password=x&username=";echo <M>$((<A>*<B>))<M>;echo "
# M, A, B random per probe; confirm response contains <M><A*B><M>
```

The injected username closes the quoted `find` argument, runs the benign
`echo`, and reopens the quote the command closes itself — mirroring the public
PoC's `";id;echo "` structure. Only a shell arithmetic expansion is echoed —
**no file is read or written and no state changes**. A server that merely
reflected the request would contain the literal `$((A*B))` expression, never the
product, so a marked-product match proves a shell evaluated it. No credential or
cookie is sent and redirects are not followed.

**Limitation:** the check reads the product from the command output the CGI
reflects in its response. A vulnerable instance that executes the command but
suppresses or redirects its output produces no match and is not reported — a
conservative false negative, never a false positive.

## Remediation

Upgrade XWEB EVO to 5.7.0, the final fixed release. Because the product is
End-of-Software-Support, no further patches will ship; for deployments that
cannot upgrade, restrict network access to the XWEB EVO web interface to
trusted clients and place it behind an authenticating reverse proxy.
