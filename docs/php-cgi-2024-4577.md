# PHP-CGI CVE-2024-4577 argument injection remote code execution

**CVE-2024-4577** re-opens the CVE-2012-1823 argument injection on Windows. When
PHP runs as php-cgi under Apache with certain Windows code pages, "Best-Fit"
character conversion folds the soft hyphen `0xAD` (sent as `%AD`) to an ASCII
hyphen, so `%ADd` reaches php-cgi as the `-d` option the 2012 patch was meant
to block (CWE-78).

```text
POST /?%ADd+allow_url_include%3d1+%ADd+auto_prepend_file%3dphp://input
Content-Type: application/x-www-form-urlencoded

<?php echo 1234*5678;?>
```

## Affected and fixed versions

PHP **8.1.*** before **8.1.29**, **8.2.*** before **8.2.20**, **8.3.*** before
**8.3.8**, when Apache runs php-cgi on Windows. DEVCORE confirmed exposure on
code pages 932 (Shift-JIS), 936 (GBK), and 950 (Big5). Other code pages may
also be affected. PHP 8.0.x, 7.x, and 5.x had reached end of life by the
June 2024 disclosure. Migrate those deployments to a supported release.

## How the detection confirms it, safely

The check submits a bounded request and reports a finding only if the server
returns the computed result. A response that merely echoes the input is
insufficient. The check sends no credentials, follows no redirects, and
caps the response size. It targets `/` only and can miss php-cgi
deployments that run PHP exclusively under a non-root path.

## Remediation

Upgrade PHP to 8.1.29, 8.2.20, 8.3.8 or later. Prefer PHP-FPM or mod_php over
php-cgi; if php-cgi on Windows must stay, avoid the affected code pages and make
sure Apache does not pass the raw query string to the php-cgi binary. The flaw
is actively exploited and in the CISA KEV catalog, so review the host for web
shells, unexpected scheduled tasks and new accounts, and rotate any secrets the
web process can read.
