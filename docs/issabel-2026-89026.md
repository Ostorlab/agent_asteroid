# Issabel Framework CVE-2026-89026 hard-coded PBX API JWT key

**CVE-2026-89026** is a hard-coded cryptographic key in the Issabel Framework PBX
API (CWE-321): bearer tokens are signed with a shared hard-coded HS256 key, so
anyone who knows the key forges an admin token and reaches the PBX API, which can
originate calls and run AMI actions as the Asterisk user.

```text
GET /pbxapi/manager/extensionstate?extension=1000&context=from-internal
Authorization: Bearer <HS256 JWT signed with the hard-coded key>
```

- VulnCheck advisory: <https://www.vulncheck.com/advisories/issabel-pbx-hard-coded-jwt-key-rce-via-pbxapi-manager-originate>.
- Fix commit: <https://github.com/IssabelFoundation/framework/commit/b97dbaf0b71c1c36f841e672b664afbeb02773bd>.
- CVE record: <https://www.cve.org/CVERecord?id=CVE-2026-89026>.

## Affected and fixed versions
Issabel Framework before commit **b97dbaf**; update to a later build that uses a
per-install random key.

## How the detection confirms it
A differential of two read-only `GET`s: first a token signed with an unrelated
key (must be rejected with 401/403), then a token signed with a known hard-coded
key. A finding needs the hard-coded-key token to answer HTTP 200 with the
extension-state markers (`"Response":"Success"`, `"Message":"Extension Status"`,
`"Exten":"1000"`), proving tokens are forgeable. Only a read-only extension-state
query is made; no PBX action is run and no state changes.

## Remediation
Update Issabel Framework to a build after commit b97dbaf that uses a per-install
random PBX API key, rotate the key, and restrict `/pbxapi/` to trusted networks.
