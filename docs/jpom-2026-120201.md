# Jpom unauthenticated auth bypass CVE-2026-120201

**CVE-2026-120201** is an unauthenticated authentication bypass in Jpom
2.10.0 through 2.11.12 (CWE-943). The `JPOM-USER-TOKEN` request header is
passed into Hutool's `Condition` parser instead of being compared as a
literal token, so a value such as `is not null` matches any stored session
and grants an attacker super-administrator access.

**Affected:** Jpom 2.10.0 through 2.11.12

**Fixed:** a version later than 2.11.12

**Severity:** CVSS 3.1 9.8 (Critical) — `AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H`

## How does the detector verify it?

This is an **active, non-destructive, differential** check. A baseline
request with no token must be refused, and only a second, otherwise identical
request carrying the bypass header may disclose the account's own profile:

```
POST /user/user-basic-info            # baseline: no header -> refused (no md5Token)
POST /user/user-basic-info
JPOM-USER-TOKEN: is not null           # bypass: discloses md5Token + systemUser
```

Requiring the baseline to be refused rules out an endpoint that discloses the
profile unconditionally; only a target where the header itself flips the
outcome is reported. Both requests are single bounded reads of the account's
own profile endpoint — no data is written, no credential is guessed, and
redirects are not followed.

## Remediation

Update Jpom to a version later than 2.11.12 that validates the
`JPOM-USER-TOKEN` header as a literal token. Restrict network access to the
Jpom server console to trusted clients.
