# CVE-2025-31125: Vite dev-server @fs file disclosure

**CVE-2025-31125 is a network-exposed file disclosure** in the Vite development
server (CWE-200 / CWE-284, CVSS 3.1 5.3). The `/@fs/` endpoint with the
`?import&?inline` query returns the content of non-allowed files inlined as a
base64 `data:` URI, bypassing the served-root restriction. Only servers
explicitly exposed to the network (`--host` / `server.host`) are affected.

**Affected:** Vite dev server exposed to the network, before 6.2.4 / 6.1.3 (and
the corresponding patched releases on older branches)

**Fixed:** Vite 6.2.4, 6.1.3 and the backported patched releases

**Severity:** CVSS 3.1 5.3 (Medium) — `AV:N/AC:H/PR:N/UI:R/S:U/C:H/I:N/A:N`

## How does the detector verify it?

This is an **active, non-destructive** check. It requests `/etc/passwd` through
the `@fs` endpoint, decodes the inlined base64 blob the server returns and
confirms the account listing:

```
GET /@fs/etc/passwd?import&?inline=1.wasm?init
GET /@fs/../../../../../../../etc/passwd?import&?inline=1.wasm?init
# response is a JS module:  export default "data:...;base64,<blob>"
# decode <blob> and confirm it contains  root:...:0:0:
```

Decoding the server's own base64 encoding and matching `root:...:0:0:` proves
the traversal returned the real file rather than merely echoing a data URI.
Only the world-readable `/etc/passwd` is read — **no file is written and no
command is run**. The percent-encoded path is kept on the wire via the raw-path
transport. No credential or cookie is sent and redirects are not followed.

**Limitation:** the check reads `/etc/passwd`, so it only confirms hosts where
that file exists and is readable (typical Linux). A Windows host, or a server
not bound to the network, is a conservative false negative, never a false
positive.

## Remediation

Upgrade Vite to 6.2.4, 6.1.3 or the patched release for your branch. Do not
expose the development server to untrusted networks: avoid `--host` and
`server.host`, or restrict access to it.
