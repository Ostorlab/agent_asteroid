# Splunk CVE-2026-20253 unauthenticated PostgreSQL recovery endpoint

An affected Splunk build exposes the PostgreSQL recovery backup endpoint without enforcing authentication, enabling unauthenticated access to a sensitive sidecar interface.

```text
POST /en-US/splunkd/__raw/v1/postgres/recovery/backup
```

## References
- NVD: <https://nvd.nist.gov/vuln/detail/CVE-2026-20253> (published 2026-06-10 by the Cisco CNA, CVSS 3.1 9.8).
- Splunk advisory SVD-2026-0603: <https://advisory.splunk.com/advisories/SVD-2026-0603>.
- CVE record: <https://www.cve.org/CVERecord?id=CVE-2026-20253>.

## How the detection confirms it, safely
One `POST` of an empty backup request with the documented default credential. A finding needs HTTP 400 and a `Failed to decode` error, proving the endpoint processes input without valid authentication. No file content is sent and no backup is created.

The `Authorization` header cannot be sent through the anonymous `defensive_http` transport, so this detection uses the scanner session directly.

## Remediation
Apply the Splunk fix in SVD-2026-0603 and restrict access to the splunkd management interface.
