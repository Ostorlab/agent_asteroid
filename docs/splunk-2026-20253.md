# Splunk CVE-2026-20253 unauthenticated PostgreSQL recovery endpoint

**CVE-2026-20253** is an authentication weakness in Splunk Enterprise’s
PostgreSQL recovery backup interface.

```text
POST /en-US/splunkd/__raw/v1/postgres/recovery/backup
```

## References
- NVD: <https://nvd.nist.gov/vuln/detail/CVE-2026-20253> (published 2026-06-10 by the Cisco CNA, CVSS 3.1 9.8).
- Splunk advisory SVD-2026-0603: <https://advisory.splunk.com/advisories/SVD-2026-0603>.
- CVE record: <https://www.cve.org/CVERecord?id=CVE-2026-20253>.

## How the detection confirms it
One `POST` of an empty backup request with the documented default credential. A finding needs HTTP 400 and a `Failed to decode` error, showing that the endpoint accepts the default credential. No file content is sent and no backup is created.

The `Authorization` header cannot be sent through the anonymous `defensive_http` transport, so this detection uses the scanner session directly.

## Remediation
Upgrade Splunk Enterprise to **10.0.7** or **10.2.4** or later on the
applicable branch, as specified in SVD-2026-0603. Restrict access to the
splunkd management interface.
