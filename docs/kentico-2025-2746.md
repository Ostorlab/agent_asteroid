# Kentico Xperience 13 CVE-2025-2746 Staging Service authentication bypass

Kentico Xperience 13 before Hotfix 13.0.178 mishandles Staging Service
authentication when no username/password is configured, so the SOAP endpoint
`/CMSPages/Staging/SyncServer.asmx` accepts an unauthenticated synchronization
task via a forged WS-Security token (CWE-288).

- NVD: <https://nvd.nist.gov/vuln/detail/CVE-2025-2746> (published 2025-03-24 by the VulnCheck CNA, CWE-288, CVSS 3.1 9.8).
- Kentico hotfixes: <https://devnet.kentico.com/download/hotfixes>.
- watchTowr write-up: <https://github.com/watchtowrlabs/kentico-xperience13-AuthBypass-wt-2025-0011>.
- CVE record: <https://www.cve.org/CVERecord?id=CVE-2025-2746>.

## Affected and fixed versions
Kentico Xperience 13 before **Hotfix 13.0.178**.

## How the detection confirms it, safely
One anonymous SOAP `POST` whose `stagingTaskData` carries a random 32-char
marker. A finding needs the service to echo that marker in a `<wsa:Action>`
response (text/xml) with none of the authentication-error strings present.
Because the marker is random, this proves the task was processed. No staging data
is created; the request is bounded.

## Remediation
Apply Kentico Xperience 13 Hotfix 13.0.178 or later, configure the Staging
Service with a strong password, and restrict access to `/CMSPages/Staging/`.
