# CVE-2026-0768: Langflow unauthenticated RCE via validate_code

**CVE-2026-0768 is an unauthenticated remote code execution** in Langflow
(CWE-94, CVSS 3.0 9.8). `POST /api/v1/validate/code` is exposed without
authentication and evaluates default-argument expressions at
function-definition time, so a default argument that calls `exec()` runs
arbitrary Python without authentication.

**Affected:** Langflow <= 1.2.x

**Fixed:** a release that authenticates the validate/code endpoint and does not
execute submitted code

**Severity:** CVSS 3.0 9.8 (Critical) — `AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H`

## How does the detector verify it?

This is an **active, non-destructive, unforgeable** check. It submits code whose
default argument raises a random arithmetic product computed in pure Python, and
confirms that product (never the literal `A*B` expression the request carries)
appears in the response:

```
POST /api/v1/validate/code    Content-Type: application/json
  {"code": "def exploit(cd=exec('raise Exception(str(<A>*<B>))')): pass"}
# A, B random per probe; confirm response contains the product A*B
```

Only a pure-arithmetic expression is evaluated — **no OS command is run and no
file is read**. A server that merely echoes the submitted code cannot contain
the product, so a match proves the server executed the Python. No credential or
cookie is sent and redirects are not followed.

**Limitation:** the check reads the product from the exception message the
endpoint surfaces in its response. A vulnerable server that executes the
submitted code but returns a sanitized or generic error (no exception text)
produces no match and is not reported — a conservative false negative, never a
false positive.

## Remediation

Upgrade Langflow to a version that authenticates the validate/code endpoint and
does not execute submitted code. Restrict network access to the Langflow API to
trusted clients.
