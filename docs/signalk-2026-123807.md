# Signal K Server CVE-2026-123807 unauthenticated resources path traversal

**CVE-2026-123807** is an unauthenticated path traversal in the Signal K Server
v2 resources API. The route
`GET /signalk/v2/api/resources/:resourceType/:resourceId` passes the
caller-supplied `resourceId` to the configured resource provider without
validation. In `@signalk/resources-provider` **1.0.0 through 1.5.2**
`FileStore.getResource` joins that id onto the resource type's storage directory
with `path.join` and reads the result as JSON, so an encoded multi-level
traversal such as `..%2F..%2F..%2F..%2Fsecurity.json` escapes the storage root.

On deployments with `allow_readonly=true` (a supported UI toggle that grants
anonymous read access) the read is unauthenticated; deployments with security
disabled are equally exposed. The advisory reads `<config>/security.json` for
the JWT signing secret, forges an administrator token, and creates an `Execute`
provider through `POST /skServer/providers`, which runs shell commands as the
server process. CWE-22; CVSS 3.1 9.8 `AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H`.
A deployment with security enabled and `allow_readonly=false` requires a
readonly token for the same read. Fixed in **signalk-server 2.34.0** and
**@signalk/resources-provider 1.5.3**, which resolve the path and reject ids
that are not a single path segment.

## How does the detector verify the traversal?

1. `GET /signalk` must return Signal K Server's own public discovery document:
   `server.id` is exactly `signalk-server-node`, `server.version` is a string,
   and `endpoints.v1` carries the same version plus the `signalk-http` and
   `signalk-ws` locations. This attributes the product without a banner guess.
2. `GET /signalk/v2/api/resources/notes/..%2F..%2F..%2F..%2Fpackage.json` must
   answer `200 application/json` with the Signal K config directory's own
   `package.json`: `name` is `signalk-server-config` (or `signalk-server` when
   the config directory is the install directory), the exact install-tracking
   description is present for the config package, and the provider has added
   `$source: resources-provider`. The file sits four directories above the
   `notes` resource directory, so returning it proves the id escaped the
   storage root while only reading non-sensitive install metadata.
3. If the `notes` resource type is disabled, the same traversal is tried once
   for `waypoints`. Both are standard types enabled by the bundled provider's
   default configuration; the traversal depth is identical.

The only file requested outside the resource directory is the server's own
`package.json`. The check never requests `security.json`, `settings.json`,
credentials or any other file. It sends anonymous GETs only and does not create
a token, provider, command or any other state.

A fixed provider rejects the id with HTTP `400` (`Invalid resource id provided`),
which produces no finding. A deployment that challenges anonymous resource
reads answers `401`/`403`, which also produces no finding. A lookalike that
returns a package.json-shaped body without the provider's `$source` marker is
not reported.

## What is the finding?

The finding confirms that an anonymous client can escape the resources storage
root and read a JSON file outside it. It does **not** claim that `security.json`
was read, that an administrator token was forged, or that a command was
executed: those are the advisory's follow-on steps and this check does not
perform them. The finding text states that the same traversal reaches
`security.json` according to the advisory, and recommends rotating the signing
secret and stored credentials because a vulnerable deployment may already have
been compromised.

## What does the detector miss?

- A deployment without the resources provider plugin enabled has no resource
  routes and is not reported; that is a mitigated configuration.
- A deployment with security enabled and `allow_readonly=false` answers `401`
  to the anonymous probe and is not reported, even though a readonly token
  would reach the same traversal. The check has no credentials for that state.
- A reverse proxy that mounts the server under a path prefix, strips the
  encoded traversal, or rewrites the resource path is not probed.
- A customized config directory without `package.json` may produce no finding
  even when the traversal exists.
- Network errors, timeouts, truncated responses and unsupported schemes are
  inconclusive and produce no finding; a missing finding is not proof that the
  traversal is absent.
