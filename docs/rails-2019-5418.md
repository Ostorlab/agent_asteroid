# CVE-2019-5418: Ruby on Rails file content disclosure

**[CVE-2019-5418](https://www.cve.org/CVERecord?id=CVE-2019-5418) is an
unauthenticated file content disclosure** in Ruby on Rails (CWE-22, CVSS 3.1
7.5). Rails derives the response template format from the `Accept` header
without validation, so an `Accept` header holding a path-traversal string makes
`render` read and return an arbitrary file readable by the application process.

**Affected:** Rails before 5.2.2.1, 5.1.6.2, 5.0.7.2 and 4.2.11.1 (and v3).

**Fixed:** Rails 5.2.2.1, 5.1.6.2, 5.0.7.2, 4.2.11.1 or later
([release announcement](https://weblog.rubyonrails.org/2019/3/13/Rails-4-2-5-1-5-1-6-2-have-been-released/)).

**Severity:** CVSS 3.1 7.5 (High) — `AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:N/A:N`.

## How does the detector verify the disclosure?

It sends a single anonymous `GET /` with the header
`Accept: ../../../../../../../../etc/passwd{{`. The trailing `{{` forces the
implicit-render code path that resolves the format into a file read. A positive
match requires HTTP 200 or 500 and the host account listing (`root:...:0:0:`)
in the body.

Only the world-readable `/etc/passwd` is requested. No state is changed, no
credential or cookie is sent and redirects are not followed.

## Remediation

Upgrade Ruby on Rails to 5.2.2.1, 5.1.6.2, 5.0.7.2, 4.2.11.1 or later. Do not
derive render formats from untrusted request headers, and treat any file the
application process can read as potentially disclosed.
