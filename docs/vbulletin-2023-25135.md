# vBulletin CVE-2023-25135 pre-authentication deserialization

**CVE-2023-25135** is a pre-authentication PHP object injection in vBulletin
before 5.6.9 PL1 (CWE-502). The `user[searchprefs]` field of
`/ajax/api/user/save` is passed to `unserialize` during input validation, before
any authentication or security-token check, so an unauthenticated attacker
reaches a deserialization gadget chain and can execute code.

```text
POST /ajax/api/user/save
user[searchprefs]=<serialized Monolog gadget that var_dumps a random token>
```

## Affected and fixed versions
vBulletin before **5.6.9 Patch Level 1**; fixed in **5.6.9 PL1**.

## How the detection confirms it
One anonymous `POST` sends a benign Monolog gadget whose only effect is to
`var_dump` a random 14-character token that the scanner generates for this probe.
A finding needs HTTP 200, an `application/json` body, and the token reflected as
PHP `var_dump` output (`string(14) "<token>"`). Because the token is fresh per
probe and only appears if the server deserialized the payload and ran the
var_dump processor, the proof is unforgeable. No command is run, no file is read
or written, no account is created, and the invalid security token means the save
does not persist.

## Remediation
Upgrade vBulletin to 5.6.9 Patch Level 1 or later and apply the vendor security
patch; restrict admin and API endpoints to trusted clients.
