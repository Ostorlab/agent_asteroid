# Langflow AI CVE-2025-34291 permissive CORS reflection

Langflow AI <= 1.6.9 reflects an arbitrary `Origin` with `Access-Control-Allow-Credentials: true` (CWE-942), so any site can make credentialed cross-origin requests to the API.

## References
- NVD: <https://nvd.nist.gov/vuln/detail/CVE-2025-34291> (published 2025-12-05 by the VulnCheck CNA, NVD CVSS 3.1 8.8).
- Project: <https://github.com/langflow-ai/langflow>.
- CVE record: <https://www.cve.org/CVERecord?id=CVE-2025-34291>.

## Affected and fixed versions
Langflow AI **<= 1.6.9**.

## How the detection confirms it
A Langflow fingerprint, then a CORS preflight (`OPTIONS`) with an attacker `Origin` (needs it reflected in `Access-Control-Allow-Origin` with `Access-Control-Allow-Credentials: true`). Only CORS headers are read.

The `Origin` header cannot be sent through the anonymous `defensive_http` transport, so the scanner session is used directly.

## Remediation
Upgrade Langflow and configure a strict CORS allow-list.
