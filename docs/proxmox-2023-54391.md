# Proxmox VE CVE-2023-54391 TFA-challenge authentication bypass

Proxmox VE 7.0 through 8.0 (`libpve-access-control` before 8.0.4) lets an
unauthenticated attacker authenticate as any enabled user without a configured
second factor by supplying an arbitrary `tfa-challenge` value to the access
ticket API (CWE-304), including the `root@pam` account.

- Proxmox fix commit: <https://git.proxmox.com/?p=pve-access-control.git;a=commit;h=032e7d6d441f89a48cadfd7f47e957c8a561c022>.
- Proxmox advisory thread: <https://forum.proxmox.com/threads/proxmox-virtual-environment-security-advisories.149331/>.
- CVE record: <https://www.cve.org/CVERecord?id=CVE-2023-54391>.

## Affected and fixed versions
The issue affects Proxmox VE **7.0 through 8.0** with
`libpve-access-control` earlier than **8.0.4**. Migrate off the end-of-life
7.x series and use a supported, fully patched release.

## How the detection confirms it
One anonymous `POST` to the access ticket API supplying an arbitrary
`tfa-challenge`. A finding needs HTTP 200, an `application/json` content type, and
an issued ticket (`"data"` with `"ticket"`). The request only obtains a ticket to
confirm the bypass; no configuration changes.

## Remediation
Upgrade `libpve-access-control` to 8.0.4 or later; the affected 7.x releases are
end of life. Restrict access to the Proxmox API, rotate credentials (any account
including `root@pam` could be impersonated), and review logs for ticket requests
carrying a `tfa-challenge`.
