# CVE-2026-114509: Laravel TokenGuard authentication bypass

**CVE-2026-114509 is an authentication bypass** in Laravel's token-based
`TokenGuard` (CWE-1287/CWE-287, CVSS 4.0 9.2). When an API guard is configured
with `driver => token` and `hash => false`, the guard does not reject a
non-string credential before the database lookup. A JSON body
`{"api_token":[0]}` becomes `whereIn('api_token', [0])`; under affected
MySQL/MariaDB implicit casting every varchar token not starting with a digit
evaluates to `0`, so the first user row is returned to an unauthenticated
attacker.

**Affected:** Laravel framework before 12.68.0 and before 13.29.0, on a
TokenGuard API guard with `hash => false` over MySQL/MariaDB.

**Fixed:** Laravel 12.68.0, 13.29.0 or later.

**Severity:** CVSS 4.0 9.2 (Critical) —
`AV:N/AC:L/AT:P/PR:N/UI:N/VC:H/VI:H/VA:H/SC:N/SI:N/SA:N`

## How does the detector verify it?

This is an **active, non-destructive** check. It sends the benign array
credential to the common API-user endpoints and confirms the response is a JSON
user record:

```
GET /api/user   (also /api/me, /api/profile, /api/v1/user)
  Content-Type: application/json
  Accept: application/json
  {"api_token":[0]}
# confirm: HTTP 200, Content-Type application/json,
#          body contains "id": <digits> AND "email": "...@..."
```

A patched guard (or a non-vulnerable database) rejects the array credential and
answers `401`/`"Unauthenticated."` with no user record. Observing a real user
record returned for a request that carries no valid token proves the
type-confusion bypass matched an existing user. The request writes nothing,
sends no token or cookie, and no redirect is followed; only the record the
bypass discloses is read, bounded to 64 KiB.

**Limitation:** the check only reports when one of the four probed endpoints
returns a JSON user record. An application that exposes its user endpoint at a
different route, or runs on a database whose casting does not coerce the token
column, is not reported (a conservative false negative, never a false positive).

## Remediation

Update Laravel framework to 12.68.0, 13.29.0 or later. Where feasible, hash API
tokens and validate that the supplied credential is a string before the lookup.
