# CVE-2026-116747: Kener authentication bypass via hardcoded fallback JWT secret

**CVE-2026-116747 is an authentication bypass** in Kener (CWE-321, CVSS 3.1
8.1). Kener 3.0.0 before 4.1.10 falls back to the hardcoded JWT secret
`DUMMY_SECRET` when `KENER_SECRET_KEY` is unset or empty, so an unauthenticated
attacker can forge session cookies and password-reset tokens signed with that
known key.

**Affected:** Kener 3.0.0 before 4.1.10

**Fixed:** Kener 4.1.10

**Severity:** CVSS 3.1 8.1 (High) — `AV:N/AC:H/PR:N/UI:N/S:U/C:H/I:H/A:H`

## How does the detector verify it?

This is an **active, non-destructive** check. It forges an HS256 password-reset
token signed with `DUMMY_SECRET` for a random, guaranteed-nonexistent `.invalid`
account and submits it, then keys on the signature-acceptance differential:

```
POST /account/forgot/api/password-reset    Content-Type: application/json
  {"receivedToken": "<HS256(DUMMY_SECRET) for kener-probe-<rand>@<rand>.invalid>",
   "newPassword": "<random>"}
# vulnerable -> HTTP 401 "User does not exist"  (signature accepted, user lookup fails)
# patched    -> HTTP 401 "Invalid or expired token"  (signature rejected)
```

The forged account lives under the reserved `.invalid` TLD, so it **cannot
exist**: the request fails at user lookup and **no password is ever changed and
no state is modified**. Only a server that validated the forged token with the
fallback secret returns "User does not exist", so that response proves the
hardcoded secret is in use. No cookie or Authorization header is sent and
redirects are not followed.

**Limitation:** the check relies on the distinct "User does not exist" vs.
"Invalid or expired token" messages at this endpoint. A deployment that has set a
real `KENER_SECRET_KEY` rejects the forged signature and is correctly not
reported; a build that returns a generic error for both cases produces no match
— a conservative false negative, never a false positive.

## Remediation

Update Kener to 4.1.10 or later. Always set a strong, unique `KENER_SECRET_KEY`
and never run with the `DUMMY_SECRET` fallback.
