# Pentaho BA Server CVE-2022-43939 non-canonical URL authorization bypass

Hitachi Vantara Pentaho BA Server before 9.4.0.1 / 9.3.0.2 makes authorization decisions on non-canonical URL paths (CWE-287), so appending `/require.js` to a protected API bypasses the check.

## References
- NVD: <https://nvd.nist.gov/vuln/detail/CVE-2022-43939> (published 2023-04-03 by the Hitachi Vantara CNA, CVSS 3.1 8.6).
- Pentaho advisory: <https://support.pentaho.com/hc/en-us/articles/14455394120333>.
- CVE record: <https://www.cve.org/CVERecord?id=CVE-2022-43939>.

## How the detection confirms it
A fingerprint of the Pentaho login page, then a `GET` of the LDAP config API through the `/require.js` suffix. **Confirms the bypass only when both hold:** HTTP 200; `application/json` content type. Only configuration metadata is read; requests are bounded.

## Remediation
Upgrade Pentaho BA Server to 9.4.0.1 / 9.3.0.2 or later and enforce canonical-path authorization.
