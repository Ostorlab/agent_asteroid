# Windmill CVE-2026-29059 unauthenticated path traversal

**CVE-2026-29059** is an unauthenticated path traversal in
[Windmill](https://github.com/windmill-labs/windmill), an open-source
developer platform and workflow/job engine. The unauthenticated job-log
endpoint builds a filesystem path by joining its `filename` segment onto the
job-log directory without normalization or containment (CWE-22), so an
anonymous request with encoded `../` segments reads any file the backend
process can read.

The route is:

```text
GET /api/w/{workspace}/jobs_u/get_log_file/{filename}
```

The `jobs_u` prefix is Windmill's unauthenticated job surface, so no token or
session is required. A request such as

```text
GET /api/w/_/jobs_u/get_log_file/..%2f..%2f..%2f..%2f..%2f..%2fetc%2fpasswd
```

returns `/etc/passwd`. Because any file the worker process can read is
reachable, the practical impact is disclosure of deployment configuration,
database credentials, OAuth secrets and worker tokens — several write-ups note
the read can be chained toward remote code execution and report active
exploitation in the wild.

## Affected and fixed versions

All releases before **1.603.3** are affected; the traversal is fixed in
**1.603.3** by commit `de2f5d3432ab294e39167b1a2b804616fc96c814`. Deployments
that embed Windmill (for example the Nextcloud Flow integration) must be
updated as well.

## How the detection confirms it, without reading anything sensitive

The detection is read-only and makes three anonymous `GET` requests:

1. **Attribution** — `GET /api/version` returns Windmill's plain-text
   `<edition> v<semver>` string (e.g. `EE v1.879.0`). A target that does not
   return this version string is not reported.
2. **Control** — `GET /api/w/_/jobs_u/get_log_file/windmill-asteroid-<random>`
   requests a non-existent, non-traversal log file. If this benign response
   already contains `/etc/passwd` content, the endpoint is not a genuine
   traversal oracle and nothing is reported.
3. **Evidence** — the vulnerable route is asked for `/etc/passwd` through
   encoded `..%2f` segments. The finding is reported only when the response is
   HTTP 200, matches `root:[x*]:0:0:`, and is not an HTML error page.

`/etc/passwd` is a world-readable account listing that contains no secret; the
detection reads only it and the short version string. It sends no credential,
cookie or request body, follows no redirect, and changes no state. All reads
are byte-capped and bounded by a deadline.

## Remediation

Upgrade to Windmill 1.603.3 or later. Until then, resolve the `get_log_file`
filename with `os.path.realpath`/`pathlib.Path.resolve` and reject any path
outside the intended job-log directory, and block `/api/w/*/jobs_u/get_log_file/`
requests whose decoded path contains `..` at the reverse proxy. Treat any file
the log process can read as disclosed: rotate database credentials, OAuth
secrets and worker tokens, and review access logs for `get_log_file` requests
carrying encoded dot segments.
