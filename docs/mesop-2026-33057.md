# Mesop CVE-2026-33057 ai/sandbox unauthenticated RCE

**CVE-2026-33057** is an unauthenticated remote code execution in Mesop
(CWE-94, CVSS 3.1 9.8). Mesop <= 1.2.2 ships a debugging Flask server at
`ai/sandbox/wsgi_app.py` whose `POST /exec-py` route accepts base64-encoded
Python source in a `code` form field and imports it with no authentication.

**Affected:** Mesop <= 1.2.2

**Fixed:** 1.2.3 (removes the ai/sandbox debug route)

**Severity:** CVSS 3.1 9.8 (Critical) — `AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H`

## How does the detector verify it?

This is an **active, non-destructive, unforgeable** check. It submits
base64-encoded Python that only raises an exception carrying a random hex
marker, and confirms that marker (never sent in plain text, only inside the
base64 payload) appears in the response:

```
POST /exec-py    Content-Type: application/x-www-form-urlencoded
  code=<base64 of: raise Exception("<random hex marker>")>
# confirm the marker and HTTP 500 in the response
```

Only an exception raise is evaluated — **no OS command is run and no file is
read**. A server that merely echoes or rejects the payload cannot contain the
marker, so a match proves the server decoded and executed the submitted
Python. No credential or cookie is sent and redirects are not followed.

**Limitation:** the check reads the marker from the traceback/error text the
route surfaces in its response. A vulnerable server that executes the code
but returns a sanitized or generic error produces no match and is not
reported — a conservative false negative, never a false positive.

## Remediation

Upgrade Mesop to 1.2.3 or later, which removes the ai/sandbox debug route.
Restrict network access to Mesop applications to trusted clients.
