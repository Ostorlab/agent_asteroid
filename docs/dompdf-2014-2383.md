# dompdf CVE-2014-2383 local file inclusion

**CVE-2014-2383** lets an attacker read local files through dompdf. `dompdf.php`
before 0.6.1, when `DOMPDF_ENABLE_PHP` is enabled, passes the `input_file`
parameter to PHP stream wrappers, so a `php://filter` resource bypasses the
chroot and reads any file the web process can read (CWE-200).

```text
GET /dompdf.php?input_file=php://filter/resource=/etc/passwd
```

## References
- NVD: <https://nvd.nist.gov/vuln/detail/CVE-2014-2383> (published 2014-04-28, CWE-200, CVSS 2.0 6.8).
- Fix commit: <https://github.com/dompdf/dompdf/commit/23a693993299e669306929e3d49a4a1f7b3fb028>.
- CVE record: <https://www.cve.org/CVERecord?id=CVE-2014-2383>.

## Affected and fixed versions
dompdf before **0.6.1** with `DOMPDF_ENABLE_PHP` enabled.

## How the detection confirms it
One anonymous `GET` of `dompdf.php` (and the PhpSpreadsheet-bundled path) asking
for `/etc/passwd` through the `php://filter` wrapper. A finding needs HTTP 200, a
`application/pdf` attachment and the `root:...:0:0:` account line in the body.
Only `/etc/passwd` -- a world-readable file with no secret -- is read; the
request is bounded, sends no credential or cookie and follows no redirect.

## Remediation
Upgrade dompdf to 0.6.1 or later and keep `DOMPDF_ENABLE_PHP` disabled. Do not
expose `dompdf.php` to untrusted clients; treat any file the web process can read
as potentially disclosed.
