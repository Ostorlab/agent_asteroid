# Nginx2Shell: CVE-2026-123007 and CVE-2026-123633 nginx HTTP/2 remote code execution exposure

**CVE-2026-123007** is an HTTP/2 flow-control integer underflow that becomes an
out-of-bounds memory copy in nginx, and **CVE-2026-123633** is an HTTP/2
connection use-after-free. Both allow an unauthenticated attacker to execute
code on the nginx server (CVSS 4.0 9.2), independently of the application
behind it. CVE-2026-123007 was present since nginx 1.9.5 (2015) and affects
1.9.5 through 1.31.8; CVE-2026-123633 was present since nginx 1.19.7 and
affects 1.19.7 through 1.31.8. Both require HTTP/2 to be enabled, and
CVE-2026-123633 additionally requires nginx to forward requests to an upstream.

F5's 18 November 2026 security release fixed both in nginx **1.30.7** (stable)
and **1.31.9** (mainline). nginx Plus is fixed in 37.0.8.1 and 37.3.0.1.
Products that bundle nginx, such as OpenResty and Kubernetes ingress
controllers, remain affected until they ship an updated build.

## How does the detector verify the exposure?

1. Read the `Server` response header from one anonymous `GET` (the body is
   never read and redirects are not followed) and accept exactly one canonical
   `nginx/x.y.z` release. A single trailing distribution build note such as
   `(Ubuntu)` is retained as owner-verification context; hidden versions,
   partial versions, four-component versions, foreign products, and
   conflicting values are inconclusive.
2. Apply the vendor boundaries: affected when the release is at or above
   1.9.5 (CVE-2026-123007) or 1.19.7 (CVE-2026-123633) and below the fixed
   points 1.30.7 (stable) and 1.31.9 (mainline).
3. For `https` targets with an affected release, complete one TLS handshake
   that offers ALPN `h2` and `http/1.1` and require the server to select
   `h2`. The handshake is the only network exchange on that connection: no
   HTTP request and no HTTP/2 frame is sent, and the socket closes right
   after the protocol is negotiated.
4. Report one finding that names the applicable advisories. Fixed releases,
   releases before 1.9.5, and TLS endpoints that select `http/1.1` or select
   no protocol produce no finding.

## What are the limits?

- A clean result does not establish patch status. Distribution backports
  (for example an Ubuntu build with a fixed version number) and hidden
  version banners cannot be resolved remotely.
- Cleartext HTTP is not reported: nginx `h2c` support cannot be confirmed
  without sending HTTP/2 frames, which this check does not do.
- The ALPN probe observes the TLS endpoint that answers the scan. A CDN, WAF,
  or load balancer that terminates TLS in front of nginx may negotiate `h2`
  even if the origin nginx would not; conversely, such an intermediary may
  block parts of the attack. The finding states that exploitability is not
  demonstrated.
- CVE-2026-123633 requires nginx to forward requests to an upstream
  (`proxy_pass` and siblings). That configuration cannot be established by
  anonymous remote metadata; the finding says so explicitly.
- No exploit traffic, WINDOW_UPDATE record, credential, cookie, request body,
  or client certificate is sent, and no state is changed.

## How was the coverage verified?

- The reader module `agent/exploits/nginx_http2_exposure.py` has a dedicated
  test corpus (`tests/exploits/nginx_http2_exposure_test.py`): canonical and
  distribution release banners, hidden/partial/conflicting/foreign banners,
  every response status, redirects, transport errors, and real loopback TLS
  servers that negotiate `h2`, negotiate `http/1.1`, offer no ALPN, or refuse
  the connection.
- The detector (`agent/exploits/cve_2026_123007.py`) is covered by
  `tests/exploits/cve_2026_123007_test.py`: both branch boundaries (1.30.6 vs
  1.30.7, 1.31.8 vs 1.31.9), the 1.9.5 and 1.19.7 minimums, CVE-2026-123633
  applicability, HTTP/2 confirmation outcomes, cleartext targets, re-probe
  behavior, and real-TLS end-to-end checks.
- Live verification on 2026-11-19 against three Docker targets on a lab
  machine: nginx 1.31.8 with HTTP/2 negotiated `h2` and was reported;
  nginx 1.31.9 (fixed) with `h2` was not reported; nginx 1.31.8 with HTTP/2
  disabled (ALPN `http/1.1`) was not reported.
- End-to-end validation ran the built `agent//asteroid` image with
  `oxo scan run --agent agent//asteroid ip 192.168.1.39` against the
  vulnerable lab target over the default `https/443` asset. The scan
  completed with one Critical finding, "Nginx2Shell: nginx HTTP/2 remote
  code execution exposure (CVE-2026-123007 / CVE-2026-123633)", for
  `192.168.1.39:443`.
